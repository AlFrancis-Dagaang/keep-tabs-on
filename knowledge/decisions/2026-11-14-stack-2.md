# Architecture update: budget limits, settings and dev branch

Updates [2026-11-09-stack.md](2026-11-09-stack.md); that record stays as written.

## Context
docs/arch.md described `categories.monthly_budget` and a budget snapshot written when a month is first viewed. The built app differs: budgets are a limit log, a settings table exists, and Neon has a dev branch.

## Options
- **A (chosen):** update docs/arch.md in place to match what is built.
- B: leave it stale. Rejected: a stale arch.md already misled sessions once (the dev branch it promised didn't exist).

## Decision
Option A. The stack itself is unchanged. The data model changes are:
- `categories` has no `monthly_budget`; limits live in `budget_months`, a row per set or changed limit (null = removed). A month's limit is the latest row at or before it, so no rollover snapshot is needed.
- `settings` holds currency (PHP | USD) and `setup_done`, one row per user.
- Neon has production and dev branches (see 2026-11-14-dev-branch-for-local-work.md).

## Consequences
- The snapshot-job risk is gone; the new risk is reading limits without the month.
- Hosting and deploy details will change again when the deploy is built (build-time migrations, preview branches).
