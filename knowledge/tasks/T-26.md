## Findings
- **One form, three callers.** `app/(app)/activity/entry-form.tsx` holds `EntryForm` (Add and Edit, a `Dialog`), `EditPayment`, `DeleteEntry`. `EntryForm` is used on `/activity` (Add in the header, Edit per row) and `/accounts/[id]` (Edit per history row). `EditPayment` and `DeleteEntry` are also used by bills, debts, goals and installments; they are not touched.
- **The server side already fits.** `saveEntry` takes the fields `type, accountId, toAccountId, toName, categoryId, amount, date, payee, note, setAside` and validates them with Zod, so a phone layout only has to submit the same names (hidden inputs behind the pickers). No change to `actions.ts`, balances or validation.
- **Two layouts, chosen in JS.** Rendering both layouts in one form would submit every field twice. So the phone and desktop fields must not both be mounted. `DialogContent` only mounts after the tap, so a media-query hook (`useSyncExternalStore` on `(max-width: 767px)`, server value `false`) can pick one with no hydration mismatch. No such hook exists yet (nothing in the repo uses `matchMedia`).
- **Bottom sheet exists:** `components/ui/sheet.tsx` supports `side="bottom"` and `showCloseButton={false}` (T-25 used it for More). A `Sheet` inside a `Dialog` is two Radix dialogs; they stack by mount order (both `z-50`), which works.
- **Set aside "For" select** is inline in the desktop `Fields`; the phone More row needs the same grouped select, so it is extracted once and used by both.
- **Accounts today:** `accounts/page.tsx` renders one `Table`; `components/ui/table.tsx` already turns rows into plain cards below md, and `RowActions` renders Edit and Remove as buttons in each card's bottom row (the "⋯" menu from T-17 is gone). The approved mock has tinted cards with a ⋯ menu instead, which the table CSS cannot give (every row gets `bg-surface`, a border and a bottom action row). So the phone gets its own card list (`md:hidden`) and the table becomes `hidden md:block`; the table and its footer are otherwise untouched.
- **⋯ menu vs dialogs.** `AccountForm` and `DeleteAccount` each own a `Dialog` with its own trigger button. A Dialog opened from inside a `DropdownMenuItem` unmounts when the menu closes (Radix pitfall), so both need an optional controlled `open`/`onOpenChange` with no trigger, and the menu component holds the two open states outside the menu.
- **Card colour.** An account's `icon` is `tile:<colour>`, `cash`, a logo key (the `logos` list is empty today) or null. Only tiles carry a colour; every other value gets the grey tile colour. Logos, once added, show on the card through `AccountIcon`.
- **Tests.** `pnpm test` includes DB-backed tests on the dev branch (`db.test.ts`, `rls.test.ts`). Nothing else covers components (no jsdom). `pnpm build` is plain `next build` (no migrate).
- Lessons applying: mock placement first (satisfied by the two approved prototypes), DB host check and 3 runs for `pnpm test` (2026-11-14, 2026-11-17), tick criteria when done (2026-11-13). No schema, migration or query change, so no production step.
