## Findings
- Status added by the owner: "indicate if the set aside is ready or full, so I can act on it". Mock `prototypes/set-aside-summary.html` updated: a Status column with a clay pill (Ready to pay / Full) or a muted "₱X to go"; phone cards carry it on the "kind · out of" line; a sample-states frame shows the other cases. Rule: ready when `setAside >= outOf`, same for every kind, only the word differs by kind. Over the amount still counts as ready.
- The four helpers (`billSetAside`, `debtSetAside`, `goalSetAside`, `installmentSetAside`) are correlated-subquery expressions on their own table, already used by the eight list and detail pages. The summary selects them from each table, so the figures match by construction. No schema change, no new SQL for the sums.
- Out of columns: `goals.target`, `debts.total`, `bills.amount`, `installments.monthlyAmount`.
- The sidebar list lives in `components/app-sidebar.tsx` (`pages`); `MobileNav` reuses `NavLinks`, so one edit covers sidebar and drawer.
- Table pattern: `ui/table.tsx` card mode (first cell = title, `data-label` cells, `data-card="end"` top right, `tfoot` becomes one line). Goals page is the model for page shell, empty state and `getMoney`.
- Mock choice taken: the flat table with Kind / Item / Set aside / Out of (the first table in the mock). Not planned: the per-kind subtotal variant and the grouped-list variant (rejected), option B sidebar placement.
- Lessons applying: 2026-11-17 qualify the outer table (helpers already do; I add no raw SQL); 2026-11-14 show figure on real data (example below); 2026-11-17 DB test timeout (run DB test 3 times).
