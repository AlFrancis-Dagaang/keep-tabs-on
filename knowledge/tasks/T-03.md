# T-03: Categories and activity

## Acceptance criteria
- [ ] Settings lets me add, rename and delete spending and income categories
- [ ] Record income, expense, and transfer (from/to) with date, amount, category and payee; each appears in Activity
- [ ] Account balances follow starting + income − expenses + transfers in − transfers out (Vitest unit test covers all four)
- [ ] Filter Activity by type; delete an entry and the affected balances update

## Findings
- `balanceOf(account)` in `lib/money.ts` is the T-02 seam: it returns the starting balance. It's used by the accounts page, the account form and `startingForBalance`.
- Lesson (no negative balances): balances stay >= 0, and that covers T-03. An expense or transfer out that would take an account below zero is rejected. So is deleting an income or transfer in when the account has already spent that money.
- RLS policies do not cover foreign keys: Postgres checks FKs without RLS. If user B guesses the uuid of A's account, B could save an entry that points at it. Actions must check that every account and category id belongs to the user, under `withUser`, before inserting.
- Only `button dialog input label table` from shadcn are installed. Filter pills need no component (they're links); the type and account pickers need `select`.
- No `prototypes/` folder.
- Arch: dates and "this month" use Asia/Manila, not the server's UTC.

## Plan

### 1. Schema and migration (first, because everything else reads these tables)
- [x] `db/schema.ts` `categories`: `id`, `user_id`, `name text`, `kind text` with check constraint `in ('spending','income')`, `created_at`; unique `(user_id, kind, name)`; same "own rows" policy as accounts.
- [x] `db/schema.ts` `transactions`: `id`, `user_id`, `type text` with check constraint `in ('income','expense','transfer')`, `amount bigint` with check constraint `> 0`, `date date` (string mode), `account_id → accounts` (on delete restrict), `to_account_id → accounts` (nullable, on delete restrict), `category_id → categories` (nullable, on delete set null), `payee text` (nullable), `created_at`.
  Check constraint: transfer ⇔ `to_account_id` is set and `<> account_id`. "Own rows" policy. Export `Category` and `Transaction` types.

## Decisions (owner confirmed 2026-11-11)
1. Transfers have no category; income and expense require one.
2. Payee is optional on every type.
3. Deleting an account that has entries is blocked with "Delete its entries first".
4. Deleting a category keeps its entries, shown as "Uncategorized".
5. Shown balances stay >= 0, and exactly zero is allowed. Editing a balance may set a negative starting balance as an adjustment; the lesson gets one line saying so.
