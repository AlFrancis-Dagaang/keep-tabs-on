# T-13: Exclude accounts from net worth

## Acceptance criteria
- [x] An account has an "Include in net worth" option, on by default, set when creating or editing it on the Accounts page
- [x] Net worth on Overview and Accounts counts only included accounts; an excluded account still shows its balance, history, and works in transfers, bills, debts and goals as before
- [x] The Accounts page marks excluded accounts, so the lower total is explained
- [x] Existing accounts stay included; no balance, budget or entry changes; a unit test covers the net worth sum with and without an excluded account

## Findings
- Net worth is computed twice as `accounts.reduce(sum of balance)`: `app/(app)/page.tsx` (Overview card) and the footer of `app/(app)/accounts/page.tsx`. Nothing else uses it. A shared `netWorth` helper in `lib/money.ts` (pure, unit-tested) replaces both.
- `loadBalances` (lib/balances.ts) selects `id, name, startingBalance` per account and is the one loader for Overview, Accounts, Activity and the account page; adding the column there makes it reach every caller. Balance math (`balanceOf`) is untouched, so transfers, bills, debts and goals behave as before.
- The Accounts form (`account-form.tsx` + `actions.ts`) is name + balance with a `values` refill pattern. A missing checkbox is absent from FormData, so the action reads "present = included"; the checkbox is `defaultChecked` on create.
- No Switch component in `components/ui`; a native checkbox with the existing `Label` is the smallest thing (shadcn Switch would add a dependency for one control).
- Setup (`app/setup/`) inserts accounts without the column, so the DB default (true) applies: setup unchanged, per the owner's decision.
- Overview account tiles list every account with its balance; no tag there (owner decision).
- Deploy: Vercel runs migrations in the build and old code ignores a new column, so an additive `ADD COLUMN ... DEFAULT true NOT NULL` is safe. Existing rows become included through the default; no backfill.
- No `prototypes/`. Code graph not needed.

## Worked example (illustrative: dev holds only test accounts, so these are not your real numbers)
Accounts: Payroll 1,000.00 · Test bank 150.00 · Savings for tuition 5,000.00
- All included: net worth = 6,150.00 (today's behaviour).
- Tuition account switched off: Overview "Net worth" = 1,150.00. Accounts page footer "Net worth" = 1,150.00, with a note "Excludes 1 account (5,000.00)"; the tuition row still shows 5,000.00 and the tag "Not in net worth". Overview tile for it still shows 5,000.00.
- A transfer Payroll → tuition of 200.00: Payroll 800.00, tuition 5,200.00; net worth = 800.00 + 150.00 = 950.00 (money moved out of the counted set, so net worth drops by 200.00). This is the intended consequence of excluding, flagged in the questions.
