# T-17: Bill and installment detail pages

## Acceptance criteria
- [x] Bills: each row on Recurring bills links to `/bills/[id]` (the name is the link, same as Debts). The page shows the amount, repeat, next due date, this cycle's pixel progress and the Pay button, then a history of every payment (date, paying account, amount, note), newest first. Paying a bill (list or detail) has an optional Note field saved on the payment and shown in the history. A bill with no payments shows a short empty message; an unknown id, or another user's, gives a 404
- [x] Installments: each row on Installments links to `/installments/[id]`. The page shows "3 of 12 paid" with the pixel bar, the monthly amount, due day, paying account and the next due date (or "Finished"), then the payment history like the bill page (the pay dialog also has the optional Note), with the months paid before tracking as a muted line
- [x] Date filter: both history lists use the shared month picker and Custom range, driven by the URL. The progress and totals at the top stay over all payments; the filter only hides history rows, as on the account history page
- [x] No schema, balance, budget or due-date change; the only write change is the optional payment note (`transactions.note` already exists); below 768px the histories show as cards from the shared table; `pnpm lint`, `pnpm test` and `pnpm build` pass
- [x] Mobile cards: below 768px, Edit and Remove move into a "⋯" menu on every card that has them (Accounts, Bills, Debts, Goals, Installments, Activity, Settings, Budget), with an `aria-label` naming the item and a tap target of about 44px; the main action (Pay, Add money, Add entry) stays visible, Remove keeps its confirm dialog, desktop rows are unchanged; any new dependency is approved before it is installed
- [x] Looked at signed in on dev with real payments, light and dark, at 390px and desktop, including a 404 for a made-up id

## Findings
- Display only, no migration. Everything needed is already stored: `transactions.billId` / `installmentId` link payments, `bills.cycleStart` bounds the cycle, `installments.paidBefore` plus the payment count gives "n of N".
- The pattern to copy is `app/(app)/debts/[id]/page.tsx` (back link, `PageHeader` with the Pay button, a progress card, a history table in a Suspense with `LoadingBar`) plus the account history page for the date filter (`parseRange`, `DateFilter`, `min` from the earliest row, "no entries in this range" vs "no entries yet"). The Debts detail page has no date filter today; the filter comes from the account page's.
- Debts list rows are linked with a stretched link: `TableRow className="relative"`, `Link ... after:absolute after:inset-0` on the name, and the actions cell `relative z-10` so its buttons stay clickable. Bills and Installments rows have no link yet. The sidebar already keeps a page lit on `/<page>/[id]` (`startsWith`), so no sidebar change.
- The bill's "paid this cycle" is the list's own query: a left join on `transactions.createdAt > bills.cycleStart`, compared in SQL (lesson 2026-11-11). The detail page reuses that shape for one bill, so the number matches the list. The installment's "paid" is `paidBefore + count(all payments)`, as in the list. Both header numbers ignore the date filter.
- `payBill` and `payInstallment` insert expenses with only `payee` set, never a `note`, and Activity can't edit linked rows, so a payment's note is always empty. A note column would always be blank (see questions). The bill's and installment's own note exists and goes in the page header.
- The two histories are the same table (Date, Paid from, Amount), so one small shared server component serves both; T-18 will add edit buttons to it in one place. Debts and Goals keep their own tables (not refactored here).
- New dynamic segments `/bills/[id]` and `/installments/[id]` under the `(app)` layout: the sidebar's `usePathname()` is already inside Suspense (lesson 2026-11-13-suspense-around-usepathname), so the build should pass; `pnpm build` confirms.
- `PayBill`, `BillProgress`, `PayInstallment` and `PixelBar` already work from any page (Debts' detail uses the same pieces); the completed flash is keyed by id, so it also plays on the detail page.
- No `prototypes/` file covers T-17. No code graph needed.
