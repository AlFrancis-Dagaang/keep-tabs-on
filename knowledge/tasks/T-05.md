# T-05: Debts

## Acceptance criteria
- [x] Create a debt with total, deadline and paid-before-tracking amount
- [x] Record payment from an account: an expense linked to the debt is saved, and the progress bar shows (paid before + payments) / total
- [x] Debt detail shows payment history; the bar turns clay and flashes when fully paid

## Findings
- Arch names the shape: `debts` (name, total, deadline, paid_before) and an optional `transactions.debt_id`. Progress is computed from transactions, never stored.
- Debts copy bills almost line for line (T-04): Zod actions with `FormState`, a payment is an expense with no category and the debt's name as payee, `loadBalances(..., { lock: true })` for the >= 0 rule, own-row checks because FKs skip RLS.
- Debts have no cycle, so paid = `paid_before` + the sum of every linked expense. There's no timestamp filter, so the SQL-timestamp lesson doesn't come into play here.
- The no-negative-balances lesson is why debts exist. A payment can't take the account below zero (same check as bills).
- No category means debt payments already stay out of budgets (brief: "bill and debt payments don't count").
- `billBlocks(paid, amount)` is generic. Debts need the same math, so rename it `progressBlocks` (3 files).
- Bills flash through a window event between the pay dialog and the bar (`bill-form.tsx`). Debts need the same thing, so move that into a small hook shared by both.
- "Debt detail" needs a page per debt: `/debts/[id]`. The sidebar highlights only exact paths (`pathname === href`), so Debts wouldn't stay highlighted on the detail page. That needs a one-line fix.
- `cacheComponents` is on, so the detail page uses the Suspense pattern the other pages use.
- No `prototypes/` folder.

## Plan

### 1. Schema and migration
- [x] `db/schema.ts` `debts`: `id`, `user_id`, `name text`, `total bigint` (check `> 0`), `deadline date` (string mode, required), `paid_before bigint default 0` (check `>= 0` and `<= total`), `created_at`. Add the "own rows" policy and export a `Debt` type.
- [x] `db/schema.ts` `transactions`: `debt_id → debts` (nullable, on delete set null, so deleting a debt keeps its payments as plain expenses).
- [x] `pnpm db:generate`, read the SQL, `pnpm db:migrate`.

### 2. Shared progress pieces
- [x] `lib/money.ts`: rename `billBlocks` to `progressBlocks`, and update `lib/money.test.ts` and `bills/bill-form.tsx`. Same math, no new tests.
- [x] `components/pixel-bar.tsx`: add `"use client"` and move the flash event out of `BillProgress`. `announceCompleted(id)` fires the event, and `useCompletedFlash(id)` returns `true` for about 1s after it. `BillProgress` and `PayFields` in `bill-form.tsx` switch to these with no change in behaviour.

### 3. Debts actions
- [x] `app/(app)/debts/actions.ts`, in the same style as `bills/actions.ts`:
  - `saveDebt`: create or edit name, total, deadline and paid before (paid before is optional and defaults to 0, parsed with `parseMoney`). Edit is scoped to the user's own row and locks it. It refuses when paid before + payments > total ("Already paid ₱x. Enter at least that.").
  - `deleteDebt`: own row only. Its payments stay in Activity.
  - `payDebt`: takes debt id, account id, amount and date. Inside one `withUser` transaction it:
    1. Locks the accounts (`loadBalances` with `lock`), then the user's own debt row with `for update`.
    2. Checks the account is one of the user's own.
    3. Works out what's left: total − paid before − sum of linked expenses. The payment must be above zero and no more than that.
    4. Checks the account has the money.
    5. Inserts the expense with `debt_id`, payee = debt name, no category.

    It returns `{ ok, completed: amount === left }`.

### 4. Debts list page (criteria 1, 2)
- [x] `app/(app)/debts/page.tsx`: replace the placeholder with the bills page shape. Load the debts with their paid sum (one grouped left join, `paid_before + coalesce(sum)`), ordered by deadline, plus balances.
  Columns: debt (a link to `/debts/[id]`, total under it), deadline, progress (`DebtProgress` and "₱x of ₱y"), and actions (Record payment, disabled once paid off; Edit; Delete). Changed in apply: disabled, not hidden, because hiding it unmounts the pay form before it announces the flash.
  Empty states: no accounts (point to Accounts) and no debts yet ("Add a credit card, loan or money you owe a friend.").
- [x] `app/(app)/debts/debt-form.tsx` (client), copying `bill-form.tsx`:
  - `DebtProgress` uses `progressBlocks` and `useCompletedFlash`. After the refresh a paid debt is already 12 clay blocks, so it just flashes.
  - `DebtForm`: name, total, deadline, and paid before tracking.
  - `PayDebt`: account, amount defaulting to what's left, and date. Calls `announceCompleted` on `completed`.
  - `DeleteDebt`.

### 5. Debt detail page (criterion 3)
- [x] `app/(app)/debts/[id]/page.tsx`: Suspense, then load the user's own debt (`notFound()` otherwise) and its payments (date, account name, amount; newest first).
  It shows a back link to Debts, the header (name and deadline), the bar with "₱x of ₱y paid" and a paid-before line, `PayDebt` (disabled once paid off), and a history table.
  Empty history: "No payments yet."
- [x] `components/app-sidebar.tsx`: highlight when `pathname === href || pathname.startsWith(href + "/")`.
  Added in apply (owner approved): the links moved into a component wrapped in `<Suspense>`, with the same links unlit as the fallback. `/debts/[id]` is the first route with an unknown param, and under `cacheComponents` `usePathname()` there failed `pnpm build`.

### 6. Activity shows debt payments
- [x] `app/(app)/activity/page.tsx`: select `transactions.debtId`, and show "Debt" in the Category column when it's set (next to the existing "Bill").

### 7. RLS test and docs
- [x] `lib/rls.test.ts`: user B can't see or update A's debts.
- [x] Add a line for this plan to `knowledge/INDEX.md` (done with this plan).

## Checks
- `pnpm test`: the renamed `progressBlocks` cases, plus the RLS test for debts against the dev DB.
- `pnpm lint`, `pnpm build`.
- `pnpm dev`, signed in, at /debts:
  - Create a debt: total ₱10,000, a deadline, paid before ₱2,500. The bar shows 3 blocks and "₱2,500.00 of ₱10,000.00" (criterion 1).
  - Paid before above total is refused. Editing the total below what's paid is refused.
  - Record ₱2,500 from an account: the expense shows in Activity as "Debt", the account balance drops, and the bar shows 6 blocks (criterion 2).
  - Paying more than what's left, or more than the account holds, is refused.
  - Open the debt: history lists the payment with date, account and amount (criterion 3).
  - Pay the rest from the detail page: the bar turns clay and flashes, and Record payment is disabled (criterion 3). Repeat the payoff on the list page. Bills still flash on a full cycle (shared-hook regression check).
  - With reduced motion on, no flash.
  - Another user's debt id at `/debts/<id>` gives a 404.

## Leaving out
- Interest, minimum payments, and payment schedules (not in the brief).
- Linking an existing Activity entry to a debt, or picking a debt in the Activity form. Payments are made only from Debts.
- Deleting payments from the detail page (Activity already deletes entries).
- An overdue badge on past deadlines (not in the criteria).
- Debts on the Overview, and debts in net worth (T-08).
- Debts in first-run setup (T-09).
- A DB check that a transaction can't have both `bill_id` and `debt_id` (only our actions set them, and never both).

## Open questions (my choices, confirm)
1. Deadline required, as the criterion says. Money owed to a friend often has no deadline. Making it optional costs nothing; say if you want that.
2. A payment can't be more than what's left (no overpaying).
3. Rename `billBlocks` to `progressBlocks` and share the flash hook with bills, rather than copying the bills code. This touches working bills code; T-06 goals would be its third user.
4. Paid-off debts stay in the list with a clay bar (no archive or hide).
