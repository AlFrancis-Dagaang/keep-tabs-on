# T-10: Ship and the done signal

## Acceptance criteria
- [ ] Production deploy on Vercel with Neon production branch; Google sign-in works on the production URL
- [ ] App installs to the home screen on iOS and Android from app/manifest.ts
- [ ] I log every transaction for one full month (two paydays); at month end every account balance matches my real bank and e-wallet apps
- [ ] At least one bill completes a cycle and rolls to the correct next due date, and one past month appears in budget history

## Findings
- Almost no code: `app/manifest.ts` and icons don't exist. Everything else is owner-side setup (Vercel project, env vars, Neon production, Google/Neon Auth URLs).
- Migrations 0000–0007 exist in `db/migrations/`. The backlog says production lacks 0003–0005; 0006 (settings) and 0007 are newer, so assume production lacks 0003–0007 until checked. Production is empty (wiped 2026-11-14), so there's no data risk, but the schema must match.
- `db/roles.sql` must be run once on the production branch (app_user, NOBYPASSRLS), and production `DATABASE_URL` must be that role's pooled string. If the dev branch's app_user password was copied to production, it needs its own.
- `pnpm build` doesn't migrate. Vercel's build command stays `pnpm build`; migrations are a manual `pnpm db:migrate` with the production owner URL (see Risks).
- `proxy.ts` matcher redirects every path except `_next/static`, `_next/image`, `favicon.ico`. A signed-out fetch of `/manifest.webmanifest` or the icons would be redirected to sign-in, which can break installability. The matcher needs them excluded.
- No icon files exist besides `favicon.ico`. Install on iOS and Android needs 192 and 512 PNGs (plus a 180 apple icon for iOS), `display: standalone`, `start_url: /`, name and theme colour. Colours come from `docs/design.md`.
- Neon Auth on production: the production URL must be a trusted origin and Google's redirect must allow it. The dev branch's Auth URLs are unchecked (decision 2026-11-14), so this is unverified for both.
- Criteria 3 and 4 need a month of real use after deploy. They can't be validated at deploy time.
- No `prototypes/`. Code graph not needed.
