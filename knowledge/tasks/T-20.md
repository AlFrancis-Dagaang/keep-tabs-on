## Findings
- `transactions` already has `billId`, `debtId`, `goalId`, `installmentId`, and they mean "this entry is a payment" everywhere: progress sums (bills, debts, goals, installments pages and Overview), `isLinked()` in `lib/money.ts` (blocks plain Edit, drives Remove wording and the roll-back), `editPayment`, budget and `loadBalances`. Reusing them for linked transfers would count every set-aside transfer as a payment. So the link needs its own columns.
- Goal "Add money" is a transfer with `goalId` set into the goal's account. Goals' saved figure is the sum of `goalId` transfers. A set-aside link to a goal must therefore be a separate column too, not `goalId`.
- Progress sums use `leftJoin(transactions) ... groupBy`. A second left join on the same table for set aside would multiply rows and inflate both sums. Use a correlated subquery column per page instead.
- Bill progress counts payments with `createdAt > bills.cycleStart`; set aside must use the same cycle so it resets when the bill rolls. Compare timestamps in SQL (lesson 2026-11-11).
- Installments have no partial payment: Pay records one whole month. "Set aside" there means ₱ set aside since the last payment, against `monthlyAmount`.
- A set-aside transfer has none of the four payment columns, so `isLinked()` is false: it stays an ordinary, editable, removable transfer. `saveEntry` needs to accept and validate the new field; `EntryForm` needs the dropdown.
- Per lesson 2026-11-16 (mock placement first): `prototypes/set-aside.html` shows two options for the bars and two for the dropdown. The owner picks before apply. All numbers in it are sample, not real data (lesson 2026-11-14, show the figure on real data): the questions below carry a worked example.
- Pay "To" name: `toName` can't be reused because the `transactions_transfer` check allows it only on transfers, and `payee` already holds the bill, debt or installment name for display. So a new nullable text column `paidTo` carries it. Goals are left out: Add money goes into the goal's own account, so a name has no meaning there.
- FK ids skip RLS (schema comment): the action must confirm the chosen item id is among the user's own rows, like account and category ids.

## Decisions (owner, 2026-11-17)
1. Two labelled bars (Set aside above Paid), not one two-tone bar. For dropdown under To, only for transfers.
2. Debts and goals: Set aside is a plain running sum against the full amount; payments don't reduce it.
3. Bills: Set aside resets each cycle, counting transfers since `cycleStart` like Paid.
4. Installments: Set aside is ₱ linked since the last payment, against the monthly amount.
5. Overview shows no set-aside figures for now.
6. Pay "To" is a free-text name only, on bills, debts and installments (not goals), inside T-20, not a separate task.
7. A "Set aside" button on each row (From, To, amount) is not in T-20; the For dropdown is. It can follow later on the same columns.
