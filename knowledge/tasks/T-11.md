# T-11: Debts owed to you

## Acceptance criteria
- [ ] A debt has a direction, "You owe" or "Owed to you", chosen when creating or editing it, on the Debts page and in setup; the name label reads "Who you owe" or "Who owes you"; every existing debt shows "You owe" and behaves as before; direction can't be changed once a debt has payments or receipts
- [ ] Debts stays one page and one list; each row shows its direction label, and the Overview Debts table shows the same label
- [ ] On an "Owed to you" debt, Receive adds the amount to the chosen account's balance, shows an income entry linked to the debt in Activity, and fills the progress bar (received / total); it can't go over what is still owed; paying a "You owe" debt works as before
- [ ] Net worth stays the sum of account balances, on Overview and on Accounts; debts in either direction don't change it, and a received repayment raises it by the amount received
- [ ] A received repayment doesn't change the Budget page

## Findings
- A debt is `debts` (name, total, deadline, paid_before). Paying is an `expense` transaction with `debt_id` and no category (`payDebt` in `app/(app)/debts/actions.ts`); progress is `paid_before + sum(linked transactions)`. The same sum is copied in three places: Debts page, debt detail, Overview.
- "Receive" is the mirror: an `income` transaction with `debt_id`. No schema change to `transactions` is needed, and `budgetFor` already ignores anything with a `debtId`, so criterion 5 holds with no budget code change. Activity already labels a debt-linked row "Debt" and only offers delete, so there is no edit path to guard.
- Net worth is computed twice from accounts only (`app/(app)/page.tsx` and a footer row on `app/(app)/accounts/page.tsx`). **Owner decision, 2026-11-14 (reverses the earlier one):** debts must not enter net worth, since showing what you owe and are owed there is confusing. Net worth stays the account sum everywhere and keeps its name; the Overview debts query keeps its `.limit(5)`.
- `monthTotals` counts all `income` entries as "Income this month", so a received repayment would show there. Debt payments already count in "Expenses this month" the same way (its comment: bill and debt payments are money out).
- `saveDebt` already locks the debt row and rejects a total below what's paid; the direction lock slots in beside it. The pay balance check (`balance >= amount`) applies only to paying; receiving can't make a balance negative, so lesson 2026-11-10-no-negative-balances is respected.
- Setup renders field kinds from a `Kind` union (`repeat`, `account`, ...) with `selectClass`; a `direction` kind follows `repeat`. The setup action repeats the debt field rules (existing `shortcut:` note), so it gains the same enum.
- Deploy: Vercel builds on every push to `main` and reads `debts.direction` at once. The migration (additive column with a default, safe for old code) must reach production before the push.
- No `prototypes/`. Code graph not needed.
