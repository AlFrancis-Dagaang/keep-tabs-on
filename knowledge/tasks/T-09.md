# T-09: First-run setup and settings

## Acceptance criteria
- [x] A new user is sent to setup: currency, accounts with today's balance, spending and income categories with optional budgets, then optional bills, goals and debts
- [x] Finishing setup lands on Overview with the entered data; a returning user skips setup
- [x] Settings can change currency (PHP or USD)
- [x] A fresh account completes setup with 3 accounts and 5 categories in under 5 minutes (timed by me)

## Findings
- Nothing exists yet: no `settings` table, `/setup` route or currency state. `settings/page.tsx` already says "Currency, categories and starting over."
- Money is formatted by `formatMoney` in `lib/money.ts` (hardcoded PHP, a `shortcut:` note says T-09 replaces it). It has 55 call sites: server pages, four client forms (bill, debt, goal, entry) and `bills/actions.ts`. Ten form labels hardcode "(₱)". `parseMoney` is currency-neutral.
- Server components can't read a React context, so the owner's "context" choice only covers client components. Server pages get the currency from a cached `getCurrency()`; every `formatMoney` call gains a currency argument. A correction to what I offered: call sites do change.
- `docs/arch.md` already lists `settings: currency, setup_done`. `proxy.ts` only redirects signed-out users, so the gate for "needs setup" goes in the `(app)` layout.
- Existing users (the owner's real data, dev and later production) have no settings row. The migration backfills `setup_done = true`, PHP for every user_id found in accounts or categories, so they are not sent to setup.
- With `cacheComponents`, request data in a layout needs `<Suspense>` (lesson 2026-11-13-suspense-around-usepathname). The gate is an async component inside Suspense.
- Start over must delete in FK order: transactions first (they reference accounts, bills, debts, goals, categories), then goals, bills, debts, accounts, categories (`budget_months` cascade from categories).
- Existing save actions are `"use server"` files that export only async functions, so their zod schemas can't be imported. The setup action repeats the field rules (short `shortcut:` note) rather than refactoring five actions.
- Owner answers (2026-11-13): short fixed currency list (PHP, USD, EUR, GBP, SGD, AUD, CAD), `settings` table with a context for client components, one `/setup` page with sections.
- No `prototypes/`. Cross-cutting (touches every page), but the codebase map and grep cover it; the graph wasn't needed.

## Plan

### 1. Schema (criteria 1, 2)
- [x] `db/schema.ts`: `settings` table: `userId` uuid PK, `currency` text not null default 'PHP' with a check against the list, `setupDone` boolean not null default false, own-rows RLS. Export `Settings` type.
- [x] `pnpm db:generate`, then add to the generated SQL a backfill: `insert into settings (user_id, setup_done) select distinct user_id, true from accounts union select user_id, true from categories`. Run `pnpm db:migrate` on dev Neon. Production still needs 0003–0006 (already in the backlog).

### 2. Currency in money logic (criterion 3)
- [x] `lib/money.ts`: export `currencies = ["PHP","USD","EUR","GBP","SGD","AUD","CAD"] as const` and `Currency`; `formatMoney(centavos, currency)` using `Intl.NumberFormat("en-PH", { style: "currency", currency, currencyDisplay: "narrowSymbol" })` (cached per currency); `currencySymbol(currency)`. Remove the `shortcut:` PHP note.
- [x] `lib/money.test.ts`: update the formatMoney test; add PHP, USD ($) and symbol cases.

### 3. Getting the currency to every call site (criterion 3)
- [x] `lib/settings.ts`: `getSettings()` wrapped in React `cache`: reads the user's row through `withUser`, returns `{ currency: "PHP", setupDone: false }` when there is none.
- [x] `components/currency-provider.tsx` (client): `CurrencyProvider` and `useCurrency()`.
- [x] `app/(app)/layout.tsx`: wrap `children` in `<Suspense>` + async `SetupGate`: `redirect("/setup")` when `!setupDone`, else `<CurrencyProvider>`.
- [x] Server pages and actions (accounts, activity, bills, budget, debts, debts/[id], goals, goals/[id], Overview, `bills/actions.ts`): get `currency` from `getSettings()`, pass it to `formatMoney`.
- [x] Client forms (bill, debt, goal, entry, account, plus `limit-form` if it labels money): `useCurrency()` for `formatMoney` and replace the "(₱)" labels with `(${currencySymbol(currency)})`.

### 4. Setup page (criteria 1, 2, 4)
- [x] `app/setup/page.tsx` (outside the sidebar layout): redirects to `/` when `setupDone`; else renders the form with `PageHeader`.
- [x] `app/setup/setup-form.tsx` (client): sections, each with add/remove rows and a hint: Currency (select), Accounts (name, balance today; at least one), Spending categories (name, optional monthly budget), Income categories (name), then "Optional" Bills (name, amount, next due, repeat), Goals (name, target, deadline, account from the entered ones, already saved), Debts (name, total, deadline, paid before). Rows live in state and go to the action as one JSON field. Spending and income rows start prefilled with common names (Food, Transport, Bills, Shopping, Health / Salary, Other) so five categories take seconds; all editable and removable.
- [x] `app/setup/actions.ts` (`finishSetup`): Zod-parse the JSON with the same limits as the existing forms (names, `parseMoney`, dates, budget > 0, goal `savedBefore <= target`, debt `paidBefore <= total`); at least one account; unique category names per kind. One `withUser` transaction: insert accounts (returning ids), categories, `budget_months` for the current Manila month where a budget was entered, bills (`dueDay` from the date), goals mapped to the new account ids, debts; upsert `settings` with currency and `setupDone = true`. Errors return per-row messages; nothing is written on error. Then `redirect("/")`. Does nothing if setup is already done.
  `shortcut:` field rules repeat the existing actions'; share them if a sixth caller appears.

### 5. Settings (criterion 3)
- [x] `settings/actions.ts`: `saveCurrency(formData)` (validates against `currencies`, upserts `settings`, `refresh()`); `startOver()`: one transaction deleting in the order above, then `setupDone = false` (currency kept), then `redirect("/setup")`.
- [x] `settings/page.tsx` + `settings/start-over.tsx`: a Currency section with a select and Save; a "Start over" section with a confirm Dialog (same pattern as `DeleteAccount`) saying it deletes all accounts, entries, bills, goals, debts, categories and budgets and cannot be undone.

### Leaving out
- Sample-data exploration (brief lists it as out of scope), editing setup afterwards (the existing pages do that), converting amounts between currencies (the setting only changes display and labels; stored centavos are untouched), per-currency decimals (JPY excluded), refactoring the five save actions to share schemas, `docs/arch.md` (fixed later via `/architect`), the Overview empty state (still points to Accounts; setup makes it rare), production migrations.
