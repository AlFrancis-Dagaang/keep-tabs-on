# T-28: Phone cards, part 1: category icons, hero block, Overview, Activity and Add entry

## Acceptance criteria
- [ ] Category icons: a category can have an icon from a fixed list (about 16: food, transport, home, bills, shopping, health, and so on); one nullable `icon` on categories, no uploads; picked in Settings when adding or renaming a category, with a generic icon when none is picked. The activity rows, the Add entry Category picker and Insights/Budget rows show it
- [ ] Phone hero block: below 768px each page this task covers starts with a solid clay block holding the page's one big number, matching `prototypes/mobile-cards.html` (approved): Overview net worth with the % vs last month, Activity spent this month. Text is white; the block works in light and dark
- [ ] Phone icon cards: below 768px the Overview lists and the Activity rows are cards (icon tile, name, one muted line, amount at the right; income green, transfers a swap icon), at least 64px tall
- [ ] Add entry on phones: the amount, with the Expense/Income/Transfer tabs, sits in the hero block; Account and Category are icon cards (the chosen category shows its icon); Save stays pinned
- [ ] Unchanged: desktop (768px and up), all balance math and queries, and the pages T-29 covers; no change to any server action beyond saving a category's icon
- [ ] Phone fit and themes: tap targets at least 44px, no sideways scroll at 390px, light and dark both readable; looked at signed in on dev and on the owner's phone
- [ ] Greeting: the Overview hero's top line reads "Hello, <first name>" from the Google profile name; with no name it reads "Overview"; no setup field, no new column
- [ ] `pnpm lint`, `pnpm test` and `pnpm build` pass; `docs/design.md` and `docs/decisions/` describe the hero block, the cards and the category icons; looked at signed in on dev at 390px and desktop

## Findings
- Mock: `prototypes/mobile-cards.html` (approved, light and dark checked). The hero colour is **clay on every page**, the default; the mock's Ink and per-page options are not built (YAGNI, one colour keeps the app recognisable). Say if you want another.
- Pattern to copy: account icons. `accounts.icon` is a nullable text holding a key from a fixed list in `lib/account-icons.ts`; `parseIcon` keeps arbitrary strings out of the column; `components/account-icon.tsx` draws it (decision `2026-11-16-account-icons.md`). Category icons do the same with lucide icons, so no files.
- **Production migrates on deploy.** `vercel.json` runs the migration in the Vercel build (decision `2026-11-14-migrate-in-vercel-build.md`), so pushing to `main` adds the nullable `categories.icon` before the new code goes live. No manual production step; I never touch the production host (owner's answer, 24 Nov).
- Existing categories have no icon, so they show the generic tag icon until you pick one. No guessing from names (it is silent when wrong, and a rename would change it, the same reasons account icons rejected it).
- Phone cards today: tables turn into cards through `data-label` and `data-card` in `components/ui/table.tsx` (all pages use it); Overview uses `MiniTable` (`Table list`); Activity rows are `TableRow`s with `RowActions`. Changing `ui/table.tsx` would restyle every page at once, so T-28 does not touch it. Overview and Activity render their own `md:hidden` phone cards and keep the table `hidden md:block`, the same split Accounts got in T-26.
- The page title and description (`PageHeader`) stay on desktop; on phones the hero replaces them on the pages in this task (the title moves into the hero's top line).
- Floating + and Insights buttons already sit above the tab bar (`z-20`); the hero scrolls under nothing, so no change there.
- `ChoiceSheet` takes `choices` with `label` and `detail`; it needs an optional `icon` to draw the tile on the picker and its rows.
- Lessons applying: mock first (satisfied), check DB host before any DB command, DB tests three times, show the figure on real data, tick criteria when done. **Owed from T-26:** plan the real-device look before the phone work is called done, so step 6 stops for the owner's phone check before docs and validate.

## Left out
- The Week/Month switch, the donut and bubble charts, and Ink or per-page hero colours from the reference; Week/Month would need a new date filter and nothing here asks for it.
- The other pages (T-29): Accounts, Bills, Goals, Debts, Installments, Budget, Insights, Set aside, Settings.
- Desktop changes of any kind; guessing icons from names; a picker icon for accounts.
